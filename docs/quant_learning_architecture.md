# 自我進化量化工具資料契約

## 目標

主要學習目標為 T+3 成本後超額報酬至少 2%，且持有三日內最大回撤不低於 -4%。T+1、T+5、T+10、T+20 報酬作為輔助標籤。

所有訓練資料必須保存訊號當下可取得的資訊與時間戳，禁止使用訊號發生後才公布的基本面或新聞資料。

## 資料層

- `scan_runs`：每次盤中或盤後掃描事件。
- `stock_signals`：三個原始策略訊號。
- `candidate_events`：交叉排名後的標準候選事件，保存可交易性、阻擋原因、風險標記、每日首次合格與正式入選狀態。
- `feature_snapshots`：訊號當下的技術、量價、市場、產業與已知基本面特徵，以及資料血緣與品質旗標；決策後新聞不得回填。
- `fundamental_observations`：基本面觀測值、資料期間、發布時間與系統得知時間。
- `news_evidence`：新聞來源、發布時間、系統得知時間、證據類型與結構化內容。
- `model_versions`：模型版本、特徵版本、訓練期間、設定與樣本外指標。
- `model_validation_predictions`：每一折不可回填的樣本外預測、訓練截止日與真實結果。
- `model_challenger_evaluations`：AI 挑戰者和規則冠軍的同窗經濟績效比較與拒絕原因。
- `predictions`：正式排名、Top 3 選擇、預測機率、預期超額報酬、進場與風險區間。
- `prediction_outcomes`：正式預測的進場結果與成熟標籤。
- `backtest_results`：原始策略訊號回測結果。
- `backtest_runs`：每次回測的設定、程式版本、完成與略過數量。

## 回測成熟狀態

- `pending`：尚無可用的進場後交易日。
- `partial`：至少有 T+1，但尚未滿 20 個交易日；每次回測都會重新補齊。
- `complete`：T+20 已成熟，除非使用 `--refresh`，否則不再重算。

## 交易成本與價格基礎

- 買進手續費：0.1425%。
- 賣出手續費：0.1425%。
- 賣出交易稅：0.3%。
- 滑價：買賣各 0.1%。
- 預設基準：Yahoo Finance `^TWII` 加權指數。
- 個股價格使用 adjusted OHLC，降低除權息造成的假虧損。

舊盤中訊號因沒有歷史分鐘線，使用隔日開盤並標記 `legacy_next_day_open_intraday`。新正式預測將在後續階段保存報告完成後第一個可成交價格。

## 候選事件與正式入選

原始三策略訊號全部保存，不因篩選而刪除。`tradability_v1` 先把同批次同代號合併，再套用以下規則：

- 成交值至少 5 億元。
- 不接受接近漲跌停、量比 5 超過 10、日內位置低於 0.20，或觀察價距離超過 12% 的標的。
- 綜合分數至少 50 分；市場品質不足時可以完全不選。
- 每日正式入選最多 3 檔，同產業最多 1 檔。
- 同股當日只在首次合格事件被考慮，後續盤中批次仍保留研究快照，但不重複模擬開倉。

阻擋門檻與風險警示分開保存。成交值介於 5 至 10 億、量能未放大、量能偏急、短線漲幅偏熱、收位偏弱等情況不一定阻擋，但會成為後續模型可學習的特徵。

既有盤中報表可依時間順序回填：

```bash
venv/bin/python3 backfill_candidate_events.py
```

## 自動化資料品質閘門

GitHub cron 只負責頻繁喚醒，`automation_guard.py` 依台北時間決定早盤、午盤與尾盤是否應執行，並查詢 `scan_runs` 避免同一時段重複掃描。排程延遲到交易時段外時會回傳 `skipped`，不下載行情、不讀取舊報表，也不建立候選事件。

盤中個股報價與全市場報價覆蓋率都必須至少 65%。掃描報表與市場快照必須是同一交易日，且時間差不超過 45 分鐘。未通過時保留錯誤與 artifacts，但不得進入正式排名或 Telegram 選股報告。

## 模型升級規則

正式規則為 Champion，新訓練模型為 Challenger。Challenger 只有在 expanding walk-forward 樣本外資料上達到最低交易日與交易筆數，且成本後淨報酬、超額報酬、相對 Champion 增值、最大回撤與跨折穩定度全部通過時，才會進入人工升級審查。精確門檻見 `docs/model_governance_v2.md`。

LLM 只負責把新聞與研究結果轉成結構化證據、產生錯誤歸因與提出特徵假設；它不能直接修改正式權重或自動部署模型。

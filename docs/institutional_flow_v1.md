# 法人籌碼資料層 v1

## 目的

`institutional_flow_v1_conservative_lag` 是第二代研究資料層。它新增與價格技術指標相對獨立的法人交易行為，但目前只供影子研究，不會直接改寫正式選股排名。

## 官方來源

- 上市：臺灣證券交易所三大法人買賣超日報 `T86`。
- 上櫃：證券櫃檯買賣中心三大法人買賣明細資訊。
- 每次抓取保存來源 URL、抓取時間與原始 HTTP 回應的 SHA-256。
- 上市與上櫃回應使用不同欄位契約，分開解析；欄位數或報表日期不符時直接拒收。
- 官方來源的 429、5xx 與 TPEx 邊緣節點 `520` 會採指數退避重試；重試耗盡仍記為 `error`，不得把暫時性來源失敗誤當成無交易資料。

## 點時規則

不假設歷史上每份盤後報表的精確發布分鐘。交易日 `T` 的法人資料統一設定為 `T+1` 日 08:30（Asia/Taipei）才可用：

- `T` 日盤中與盤後決策不得使用 `T` 日法人資料。
- `T+1` 日開盤後決策可使用 `T` 日法人資料。
- 特徵建立時以 `known_at <= decision_at` 過濾，不以檔案下載時間倒推可用性。

這個設定比實際盤後發布時間更保守，目的是避免歷史回測偷看未來。

## 特徵

每個候選事件最多使用當時已知的最近 20 個法人交易日：

- 外資、投信、自營商與三法人合計的 1 日及 5 日淨買賣超股數。
- 各法人最新淨買賣超相對自身 20 日分布的 Z-score。
- 外資、投信與合計的 5 日買超比例。
- 外資、投信與合計的有方向連續買賣超天數；負值代表連續賣超。
- 外資、投信、自營商同向程度，範圍為 -3 到 +3。

少於 5 個觀察值標為 `insufficient`，5 至 19 筆標為 `partial`，20 筆才是 `complete`。缺資料不會補零。

## 儲存與自動化

- `institutional_flow_daily` 保存最近 60 個日曆日的官方逐日資料，控制 Git 追蹤主庫的體積。
- `institutional_flow_fetches` 保存每個市場、日期的成功、無資料或錯誤狀態。
- `institutional_feature_snapshots` 永久保存候選事件當下可見的衍生特徵。
- Vercel 於台北時間每個工作日 19:20 觸發 `institutional_flow.yml`，第一次執行回補 45 個日曆日，後續只抓缺漏與當日資料。
- `institutional_history.yml` 以年度分片平行回補歷史資料；每年分片可從 GitHub Release 獨立續傳，避免單一長任務失敗後重抓全部年份。
- `institutional_replay_dataset.py` 將年度分片依 `known_at <= as_of` 合併到歷史 replay dataset；年度缺漏、非終態請求、SQLite 完整性失敗或同日資料都會中止研究，輸出 gzip 與 SHA-256 可重現。
- `institutional_research.yml` 只有在 2020 至 2025 年分片全部可用後才執行。2020 年只作為 2021 年初 20 個法人交易日的暖機資料；enriched dataset 保存於 `research-institutional-data-v1` Release，不放入 Git 主庫。

## 研究治理

2021 至 2025 的既有 holdout 已經歷多輪策略比較，因此不能再被視為完全未看過的最終驗證集。法人特徵的歷史回放只可用於開發、除錯與估計方向；正式升級必須依靠 Generation 2 上線後新累積的前瞻樣本，並繼續通過成本後淨報酬、超額報酬、回撤、跨折穩定度與模擬投資門檻。

Generation 2 預先鎖定兩個比較，避免再用大量組合碰運氣：

- 次日開盤進場、T+5 持有期、Q80 棄權的同產業相對排名。
- 次日開盤進場、T+10 持有期、Q80 棄權的同產業相對排名。

每個比較只改變一件事：技術面控制模型使用原本 18 個特徵，增量模型再加入 11 個正規化法人特徵。歷史流程只計算 development 與 validation 的同窗差異，保留 holdout 不評估，且固定寫入 `prospective_generation_required`，因此無論歷史結果多好都不能自動接管正式排名。儀表板會標示「歷史診斷」、法人淨報酬增量與超額報酬增量。

## 條件式法人研究

第一輪直接增量在 T+5 與 T+10 都沒有勝過技術面控制，因此下一階段不再把更多原始欄位直接丟進模型。`institutional_attribution.py` 只讀取 development 分區，依下列事先固定的維度計算法人條件組相對同分組其他候選的逐日配對超額報酬差：

- 順勢、反轉與波段策略來源。
- 大盤與產業上漲家數廣度。
- 成交值與 20 日量比區間。
- 外資累積、投信累積、外資投信共識與三法人廣泛共識。

探索候選至少需要 200 筆條件樣本、500 筆同組控制樣本，以及 T+5、T+10 各 100 個同時存在條件組與控制組的配對交易日；兩個持有期的超額報酬差都必須為正。探索程式不讀取 validation 或 holdout 報酬，完整比較矩陣輸出為 `institutional_attribution.json`。

development 探索期鎖定的第一個候選是「外資與投信前一交易日同向買超、同向分數至少 2，且訊號當下產業上漲家數至少 55%」。其 development 逐日配對超額報酬增量為 T+5 約 0.32 個百分點、T+10 約 0.51 個百分點。這只是產生假設的資料，不是可交易結論。

`institutional_conditional_research.py` 將上述規則凍結成單一二元互動特徵，預先登記 T+5 與 T+10 兩個 Q80 同儕排名消融。兩組 validation 比較只允許改變這一個特徵，仍不查看既有 holdout，也固定禁止正式排名；即使 validation 通過，仍需全新 Generation 2 前瞻樣本確認。
